{% load static %} {% comment %} Shell for the server-rendered pages: the OAuth login/consent/error screens and the email-change result. No third-party resources, deliberately. This used to pull Tailwind from cdn.tailwindcss.com and CSS from fonts.googleapis.com — an executable script from someone else's origin on a page where users type their password, which is the one page in the product where that is least acceptable. The styles below are hand-written and cover only what these four templates use; they are far smaller than the framework they replace. Fonts come from /fonts/fonts.css, which nginx serves from the SPA build on the same origin (see `location ^~ /fonts/`). Django serves these pages under timetify.net via the /oauth/ proxy, so that path resolves. Running Django directly in dev it 404s and the system font stack takes over — cosmetic only. {% endcomment %} {% comment %} Belt and braces: these pages contain no JavaScript at all, so saying so means an injected script cannot run even if something else slips. Deliberately no `form-action`: approving consent POSTs here and is answered with a 302 to the client's own redirect_uri, and browsers have disagreed about whether form-action applies to the redirect that follows a form submission. A directive that might break the entire authorization flow in some browser buys nothing here — there is no script that could inject a form in the first place. {% endcomment %} Timetify {% block content %}{% endblock %}
