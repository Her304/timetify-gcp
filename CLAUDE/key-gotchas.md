# Key Gotchas

- **Feed `friendsList`** — flatten via `.map(f => f.friend_details).filter(Boolean)`.
- **Feed = social hub** (`components/feed/`, friends page merged in): snaps strip (`AvatarRow`, snap-only) + requests banner + stacked group/DM lists. DM sort = unread → free now (`useFriendsAvailability`) → last active; unread = red dot, subtitle = shared classes. `PeopleSearch` = friends matched **locally** (search endpoint excludes friends) + strangers from `/api/friends/search/`. Snap-to-friend: `SnapCaptureModal presetAudience` → `selected` visibility, one recipient.
- **Chat list** — `flex flex-col-reverse` DESC (index 0 = newest).
- **Snap expiry** — `expires_at` is display cliff; `is_removed` is moderation-only, not set on natural expiry.
- **Camera release** — call `window.location.reload()` after clearing course or Chrome's camera indicator sticks.
- **Course overlap** — strict `<` only; 10:00-end / 10:00-start touch allowed.
- **Profile picture** — frontend downscales ≤1024 px + JPEG @ 0.7; `profile_picture` is write-only, clients read `profile_picture_url`.
- **Profile page** (`components/user/profile.jsx`) — dark card + accordion settings (notifications / snap groups / invite), then standalone sections: **friends** (under "my week"), **all my courses** (archive), **blocked users**, then (mobile-only, `md:hidden`) a **"more from timetify"** vertical link list — about/blog/help/community/terms/privacy/github, standing in for the desktop `Footer` which is hidden below `md`. Friends list flattens to user objects (row `id` dropped — `.id` is the *other user's* id), shows 5 + show-more; per-row **chat** (icon+label pill, `POST /api/chats/ {friend_id}`, `h-8`) / **details** (opens `FriendDetailsModal`, `h-8`, same height as chat) which holds the destructive **remove**/**block** actions.
- **Invite QR** — server-rendered PNG (`GET /api/invite/qr/`, `qrcode` lib), fetched as a blob and shown inline; link/code come from `currentUser.invite_code`. The loader effect must depend **only on `openSection`** and guard on `qrUrl` — putting `qrUrl`/`qrLoading` in its deps re-runs the effect, whose cleanup cancels the in-flight fetch, so `qrUrl` stays null and only the pulsing placeholder ever shows (StrictMode makes it deterministic). Keep the `invite_code` backfill in a separate effect.
- **Unfriend** — `DELETE /api/friends/<pk>/` where **`pk` is the other user's id** (not the friendship row id); deletes both reciprocal `Friend` rows, idempotent. **Block** — `POST /api/blocks/ {user_id}` (manual block) also severs the friendship both ways; blocks surface in the profile blocked-users section. There was no unfriend/direct-block endpoint before — blocking used to come only from the report/appeal flow.
- **Archive course actions** — `details` reuses schedule's `CourseDetailsModal` via a synthetic single-entry cluster (`courseId`/`baseCourse` = `course_id`; modal re-fetches `/api/courses/` and matches by `course_id` for weeks/exams/assignments — past courses show a sparse panel since upcoming/owners filter out). `remove` = `DELETE /api/courses/<id>/` (resolves parent→child, cascades).
- **Week-view block coloring** (`week_view.jsx`) — all course blocks are one flat tone (`COURSE_TONE`: light lilac `#E5D5F2` fill, `#5A3A85` code/location text), not the old per-course `COURSE_PALETTE` hash-based rainbow (that array still exists solely to vary *friend avatar* chip colors within a block, via `avatarBgFor` — unrelated to block fill). Event blocks match the same light-tint convention in lime (see [events](events.md)). `CourseDetailsModal.jsx` still carries its own separate copy of the old 6-color `COURSE_PALETTE` for its header chip — that's a pre-existing, not-yet-reconciled inconsistency with the calendar block color.
- **`CourseBlock` cramped-height behavior** — blocks need ~66px to comfortably fit avatar + code + location; below that (`roomy = height >= 66`), the location line drops but the avatar (profile pic) always stays, just shrunk to 16px. Never drop the avatar entirely — that was tried and reverted per user feedback.
